### "logs at an old location" on every `pai` call (fixed)

Every `pai` invocation printed a one-line migration notice because
`~/.claude/logs/workers` had not moved to PAI_HOME. `pai config migrate
--logs` refused: "4 worker(s) other than the interactive session are
RUNNING" while `pai worker ps` showed one. Root cause:
`activeSpawnedWorkerCount` trusted `state: "running"` status files without
the pid liveness check `ps` applies (four files from 2026-09-17/19, processes
gone). Fix in `src/workers/logs-migrate.ts`: reuse `alive()` from
`status.ts`; and the move itself is now an atomic `renameSync` plus a
symlink at the old path (held fds follow the inode, path writers land in
the new directory), copy+verify only on EXDEV. Tests 7 → 12. Migration run:
34,953 files moved; `~/.claude/logs/workers` is now a symlink; the notice is
gone from every command.
